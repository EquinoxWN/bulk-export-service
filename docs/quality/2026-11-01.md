# Quality check, 2026-11-01 rules (checked 2026-11-17)

The owner's 10 rules, checked against the M1 code on Windows 11 with Go 1.26.11. No PostgreSQL runs
locally: the PostgreSQL tests run in CI only and have not run yet. The race detector needs cgo,
which this machine lacks; CI runs every test with `-race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | External calls are PostgreSQL (pgx) and file I/O. Both pools set a 10 s connect timeout (`source/postgres.go` `OpenPostgres`, `pgstore.Open`); every store statement has a 5 s context deadline (`pgstore.QueryTimeout`); every page runs with a per-attempt context timeout (`-page-timeout`) and a server-side `statement_timeout`. Page reads retry at most `-retries` times (0..10) with doubling, jittered backoff capped at `-max-backoff` (`worker.readPage`, `backoff`); cursor and type errors are not retried. Tests: `TestTransientFailuresAreRetried`, `TestRetriesAreBoundedAndFailureIsRecorded`, `TestPermanentErrorsAreNotRetried`, `TestBackoffIsBoundedAndGrows`, `TestOpenPostgresRejectsBadSettings` (unreachable server). Errors are returned with context; ignored results are each commented (rollback after a read-only transaction, close of a read-only file, removal of a `.part` after a failed write, JSON encode after the status line is sent). |
| 2 | Writes safe to retry | pass | Job create is idempotent per (account, key): memory map, PostgreSQL `UNIQUE (account_id, idem_key)` with `ON CONFLICT DO NOTHING`; a retry returns the first job, another body is refused. Tests: `CreateIsIdempotentPerAccountAndKey`, `ConcurrentCreateStoresOneJob` (16 goroutines, one job), API replay test. Export files are written to `.part` with `O_TRUNC`, fsynced and renamed, so a retried export never appends to an old file. Progress, finish and fail are fenced to the owning worker and may not go backwards. |
| 3 | No race conditions | pass | Shared state: the memory store and memory source (one mutex each; copies returned, `TestMemoryReturnsCopies`), the demo's failure injector (mutex). Claims are atomic (`FOR UPDATE SKIP LOCKED` in PostgreSQL): `ConcurrentClaimsTakeEachJobOnce` (8 workers, 40 jobs). Worker ids carry a random per-process part so two processes cannot share a fence. `-race`: CI only. |
| 4 | Don't trust the clock | pass | Durations use `time.Since`/`time.Now` (monotonic) and timers. Stored times are UTC: memory store uses `time.Now().UTC()`, PostgreSQL uses `timestamptz` and the store converts to UTC on read; the contract test checks `created_at` and `finished_at` are UTC. Claim order uses an identity column (`seq`) or creation order, never a timestamp. Timestamps in files and cursors are fixed-width UTC (`dataset.TimeLayout`). |
| 5 | Read before changing | pass | pgx v5.12.0 APIs used exist and compile (`pgxpool.ParseConfig`, `BeginTx` with `pgx.ReadOnly`, `CopyFrom`, `CollectRows`); PostgreSQL features used (`FOR UPDATE SKIP LOCKED`, row-value comparison, `GENERATED ALWAYS AS IDENTITY`, `pg_is_in_recovery()`, `set_config`) exist in 17. Environment variables read: `BULK_EXPORT_PRIMARY_DSN`, `BULK_EXPORT_REPLICA_DSN` (serve), `BULK_EXPORT_TEST_DATABASE_URL` (tests); all documented in the README. |
| 6 | Never break compatibility | pass | First version: the API is versioned under `/v1`; JSON responses only add optional fields (`omitempty`); the jobs table is created with `IF NOT EXISTS` and a second start works (`TestPGOpenIsRepeatableAndRejectsBadSettings`, CI). The cursor format is fixed and documented (ADR 0002). |
| 7 | One source of truth | pass | Job state lives only in the job store; the file's SHA-256 and size are stored with the job and checked by the demo against the downloaded bytes. The dataset registry (`dataset.Orders`) is the only definition of columns and key; SQL is generated from it. Go 1.26.11 in CI, README and results; `go.mod` states the minimum (`go 1.25.0`, set by pgx). |
| 8 | Small changes, no secrets, validate input | pass | No secrets: DSNs come from the environment; the CI database uses `trust` auth in a job-local container. Inputs validated: JSON body (4 KiB, strict, no trailing data), idempotency key pattern, account id, dataset, format, job id pattern on every path, worker id pattern, all CLI limits; identifiers in SQL come only from the registry and match `^[a-z_][a-z0-9_]{0,62}$`; values are bind parameters. The download path is `<out>/<id>.csv` and a stored name that differs is refused (`TestDownloadRefusesStoredPathsOutsideTheJob`). CSV formula guard on text cells. One dependency: pgx. |
| 9 | Tests that can actually fail | pass | No tautologies. The only skips are the PostgreSQL tests without `BULK_EXPORT_TEST_DATABASE_URL`, which `make test-pg` turns into a failure. Mutation check below: 15 of 15 killed. Empty, invalid and failure paths are covered for each entry point (API, store, source, worker, CLI). |
| 10 | Re-verify | pass | `bash .tmp/check.sh` twice: gofmt clean, `go vet` clean, 49 tests passed (plus 8 subtests), 7 skipped (PostgreSQL, CI only), govulncheck "No vulnerabilities found.", demo verify line with 0 mismatches, `CHECK PASS`. `python .tools/audit_repo.py bulk-export-service`: OK. CI: not run yet (no push). |

Known limitations (also in the README): no snapshot (M2), a job whose worker dies stays `running`
(M3), no authentication, CI uses a read-only role on the same server instead of a hot standby, worker
memory not measured yet.

run, `go build ./...` and `gofmt -l` confirmed every file was restored.
